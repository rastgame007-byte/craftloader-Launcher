# CraftLoader — где остановился и что дальше

## Что уже есть (v2.2 — всё работает, протестировано)

- **Моды**: Modrinth (поиск, фильтры, пагинация) + CurseForge по ссылке/слагу/ID
- **Готовые сборки**: .mrpack (Modrinth) и модпаки CurseForge → отдельная папка /
  .minecraft / просто архив
- **Свои сборки**: кнопка «＋» у версии мода → «Установить и запустить».
  На странице «Игра» все сборки карточками с кнопкой запуска
- **Запуск Minecraft**: vanilla / fabric / quilt, оффлайн-ник (без аккаунта),
  память 2–16 ГБ, файлы качаются с серверов Mojang
- **Java**: автопоиск по требуемой версии, при нехватке качается рантайм Mojang
- Обновления модов, избранное, мини-сборка «Минимальная оптимизация» (8 модов)
- Конфиг пишется атомарно; битый сохраняется в .bad вместо потери данных
- Папка mods создаётся автоматически при первом запуске — скачивание
  работает из коробки

## Как это устроено (технически)

- Go, один бинарник; UI — `ui/index.html` (вшит через go:embed), WebView2 на Windows
- `main.go` — API-сервер (127.0.0.1:случайный порт) + всё про моды/поиск/конфиг
- `launcher.go` — движок запуска: манифесты Mojang, fabric/quilt-оверлеи,
  classpath, natives, оффлайн-UUID, автозагрузка Java-рантаймов
- `packs.go` — свои сборки (CRUD + установка + резолв ссылок модов)
- `win.go` / `nix.go` — окно WebView2 / Linux-шим (CL_NOBROWSER=1)
- Данные юзера: `%APPDATA%\CraftLoader\` (Windows) — config.json,
  runtime/ (файлы игры), instances/ (сборки)
